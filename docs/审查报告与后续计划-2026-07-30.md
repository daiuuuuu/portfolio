## 二、动效系统审查：还存在的不足

按严重度排序。★ = 建议本周期解决，☆ = 可排入后续。

### ★ A1. 移动端动效从未实测

所有行为验证都在 1440px 桌面完成，390px 只测过横向溢出。未知风险：
- 逐行触发器 ~200 个/页在中低端手机上的帧率表现
- 行级 SplitText 在窄屏下行数暴增（一行变三行），触发器数量翻倍
- 滚轮阻尼对触摸滑动无影响（正确），但惯性参数未按 pointer: coarse 区分
- XCU pin 禁用后，5 张物料图在 390px 下的展示是否局促

**建议**：补一轮移动端实测（真机或 Playwright 设备模拟），必要时移动端降低 stagger 密度、关闭惯性。

### ★ A2. SplitText 不重拆行：窗口 resize 后换行点错误

拆行只在初始化时执行一次。窗口宽度变化（拖窗口、手机旋转）后，行的实际换行位置变了，但 SplitText 的行包装器还是旧的——遮罩边界会切在错误的视觉行中间。

**建议**：监听 resize（防抖 300ms）→ revert 全部 SplitText → 重跑 `initScrollReveals` → `ScrollTrigger.refresh()`。`useScrollReveals` 里加即可，约 15 行。

### ★ A3. 字体加载时序导致首次拆行可能量错行高

Google Fonts 的 Geologica/Inter 若在拆行后才加载完成，行高测量基于 fallback 字体，拆出的行数/位置会错。当前靠 `document.fonts.ready.then(refresh)` 只刷新了触发位置，**没有重拆行**。

**建议**：`document.fonts.ready` 回调里做与 A2 相同的 revert + 重建（合并为同一个 `rebuild()` 函数）。

### ★ A4. 性能没有预算，也没有低端机实测

- 单页 ScrollTrigger 实例 ~400+（行级 + 旅程 + 字幕条 + pin）
- 每个触发器都在 scroll 事件里参与计算
- 构建产物 669KB（gzip 219KB），GSAP 占 ~70KB gzip

**建议**：
- 定性能预算：滚动帧率 ≥ 50fps（中端机）、交互响应 < 100ms
- 用 Playwright trace 或 Chrome DevTools 实测一次长页面滚动
- 超预算则降级策略：移动端行级触发合并为块级（文字块整体遮罩）
- 路由级 code-split：`React.lazy` 详情页（立省 Showcase 大组件和 GSAP 首屏成本）

### ★ A5. 路由切换是硬切，没有页面过渡

首页 → 详情页是瞬间切换 + ScrollToTop 跳顶。与全站"位置驱动丝滑"的调性不符，是全站体验上最后一块粗糙的地方。

**建议**：做一个克制的过渡——旧页面 opacity 1→0（0.25s）→ 切换 → 新页面 Hero intro 自然接管。不要滑动/翻转等花哨转场，不符合品牌。可用 React Router 的 location key + 简单状态机实现，~40 行。

### ☆ A6. reduced-motion 开关分散在 6 处，缺少统一入口

`useScrollReveals`、`XcuShowcase`、`ProjectHero`、`HeroSection`、`ProjectIndexItem`（负片反转）、`smoothWheel`、`MarqueeStrip` 各自判断 `prefers-reduced-motion`。新增动效容易漏判。

**建议**：`src/animations/motionPrefs.ts` 导出 `motionOK()` 单例判断（可带 matchMedia 监听），所有动效模块统一调用。

### ☆ A7. 入场遮罩本质仍是"到线播放的时间动画"

透明度旅程已经是纯位置驱动，但遮罩仍是阈值触发后播 1.4s。用户快速滚过一个区块时，遮罩会"追播"完 1.4s——和滚动的同步感弱于旅程部分。这是当前架构里最后一处"非 scroll-driven"。

**建议**：可选升级——遮罩也改 scrub（行顶 92%→70% 区间内 clip 从 100%→0%）。优点是完全位置同步；代价是快速滚动时文字只有擦到一半的状态（没有自动播完）。**需要产品决策**：要"自动播完的从容"还是"完全同步的跟手"。我倾向前者（现状），此项记为可选。

### ☆ A8. 负片反转 overlay 的封面图重复请求

overlay 里第二张 `<img src={coverImage}>` 与原图同 URL（浏览器缓存兜底，无双倍流量），但 DOM 中两份大图节点 ×6 张卡片。移动端不需要 overlay（无 hover），却仍渲染。

**建议**：matchMedia `(hover: none)` 下不渲染 overlay DOM。

### ☆ A9. MarqueeStrip 短文案在超宽屏可能露白

`REPEATS = 8` 是估算值。文案最短的项目在 2560px+ 宽屏上，half 宽度可能不足视口 2 倍，取模循环时右端露白。

**建议**：挂载时测量，`while (halfWidth < viewport * 2) 加倍内容`，动态确定重复次数。

### ☆ A10. 触控板原生惯性 + smoothWheel 惯性可能叠加

macOS 触控板自带滚动惯性，我们拦截后又加一层惯性。实测 Windows 滚轮 OK，macOS 触控板可能出现"滑完又滑"的双重感。

**建议**：检测连续小 delta（触控板特征）时降低 `INERTIA_FACTOR` 或直接放行原生（multiplier=1）。需要真机验证后再调。

## 三·补、静态排版设计审查（基于逐屏截图观察）

> 这一章只管"静止状态下的版面"：网格、字级、密度、节奏、图片处理。不涉及动效。

### C1. 中文字体栈未定义——跨平台排版不一致（最重要）

设计 token 只定义了 Inter / JetBrains Mono / Geologica 三个西文字体，**所有中文都落在系统默认字体上**：Windows 渲染成微软雅黑，macOS 是苹方，Linux 可能是文泉驿。这意味着：
- 项目中文大标题（`project-index-title-zh`，40px/700）在每个平台长不一样
- 中西文混排时基线、字重、灰度都不统一（截图里中文标题明显比西文"虚"）
- Geologica 不含中文字形，用了它的元素中文部分静默回退

**建议**（不动设计风格）：在 globals.css 的 font token 里显式声明中文栈：
`'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei', sans-serif`。
讲究一点可以引入 Noto Sans SC（Google Fonts，只加载 400/700 两档）；不想加请求就用系统栈，至少三平台表现可预期。中文大标题建议加 `letter-spacing: 0.02em` 补偿黑体系字体的局促感。

### C2. 首页目录卡右列偏空

封面图固定 `md:w-[320px]`，放在 4/12 列里——1440px 下右列近半是空白，1920px+ 更空。卡片三列（3/5/4）的视觉重量：左（稀疏元数据）中（大标题+两段文字）右（小图），重心明显左倾。

**建议**（任选）：
- 封面放大到列宽的 80-90%（`w-full max-w-[420px]`），让右列有存在感
- 或封面右出血（突破 margin-outer 贴到视口右缘），瑞士网格里这是标准做法，和详情页 Hero 的右图出血呼应
- 元数据列的 5 项间距从 `justify-between` 改为固定 `gap-10`，避免超高屏上拉得太散

### C3. 详情页 12 个区块节奏单一

几乎每个区块都是同一配方：`py-16` + label + 大标题 + border-b 分隔。滚到中段会产生"怎么还没到尾"的疲劳感。具体三个不一致：

1. **标题处理不统一**：QualityAudit / Comparison / WorkflowCompare / Gallery / Philosophy 用 `heading-scanlines`，Strategy（DESIGN DECISIONS）、Pipeline 却用纯黑字——两种标题风格无规则混用
2. **间距全部 py-16**：没有疏密对比，重点区块（WorkflowCompare 是核心叙事）和普通区块一样平
3. **底色全白到底**：灰阶六级 token 里 surface-container/low/high 几乎没用在大区块上

**建议**（不碰设计规范）：
- 标题统一为一种处理（建议全部 scanlines，它是品牌记忆点）
- 节奏改为 py-12 / py-16 / py-24 三档：过渡性区块（Strategy、Decisions）用 py-12，叙事重区块（WorkflowCompare、ImageWorkflowShowcase）用 py-24
- 每页挑 1-2 个区块垫 `bg-surface-container-low`（如 Background、QualityAudit），在灰阶内做段落分区，让长页有"章节感"

### C4. 图片边框处理混乱

全站图片的边框规则目前是一笔糊涂账：视频有 `border-outline-variant`、画廊图没有、封面没有、GujiShowcase 扫描页没有、ImageWorkflow 右侧预览有、XCU 物料图没有。

**建议**：定一条规则写进 CLAUDE.md。推荐：**内容图一律 1px outline-variant 边线**（和卡片区隔一致，瑞士体系的图版惯例），装饰性大图（Hero 封面、philosophyBanner、XCU 横滚物料）不加。改起来就是 4-5 个组件各加一个类。

### C5. 决策问答区的 JS 测量布局脆弱

`ProjectDecisionsSection` 用 `scrollWidth` 实测问题文字宽度来定左列宽（200-520px）——字体加载晚了量错、换项目重新量、resize 不重新量。而且这是全站唯一一处"JS 定宽"的布局，和 12 列网格体系格格不入。

**建议**：改回网格布局：左列固定 `md:col-span-4`，问题文字允许换行（`whitespace-normal`），右列 `md:col-span-8`。视觉差异极小，删掉全部测量代码和 matchMedia 逻辑，~30 行代码变 0。

### C6. 首页 Hero 在宽屏上漂浮

Hero 内容盒 `max-w-4xl mx-auto`，1920px 时两侧各空 ~400px，2560px 更孤立。设计参考（对位 code.html）的 Hero 是贴边的。

**建议**：`max-w-4xl` → `max-w-6xl`，或者让上下两条 border 延伸到视口边缘（文字保持居中）——线条贴边是瑞士网格的标志性处理，零风险。

### C7. 导航与页脚的信息量偏薄

- 顶栏在首页滚动时没有当前位置指示（PROFILE/WORKS/CONTACT 无 active 态）
- Footer 只有一行版权 + 两个链接，和上面饱满的内容区相比突然"泄气"

**建议**：
- 顶栏加滚动位置高亮（ScrollTrigger 判断当前 section，给对应链接加 border-b，~20 行）
- Footer 扩展为三栏：左（版权+状态行）中（SITEMAP：6 个项目链接）右（联系方式）——还是 1px 边线 + mono 字，信息密度对齐全站

### C8. 字级体系的末端太碎

正文 `text-body-md` 14px/20px 偏小，配 `leading-relaxed`（1.625）后行高 22.75px，长段落阅读 OK；但往下还有 13px、11px、10px、9px 四级小字同时出现在一个屏里（Showcase 区尤其密），视觉噪音偏大。

**建议**：全站小字收敛为三档：12px（mono 元数据）/ 10px（label）/ 9px（辅助说明），把 13px 和 11px 的散点归并进去。这个改动面较大（约 20 处），建议 Phase 9 顺手做。

## 六、给未来维护者的三条军规

1. **新增区块先挂 data-reveal，再谈样式**——没挂属性的区块在全站动效里会"死得很突兀"
2. **opacity 归旅程管，clip-path 归遮罩管**——任何新动效不要同时碰这两个属性
3. **文案只进 projects.ts**——字幕条、卡片、详情页全部数据驱动，组件里不写死内容
