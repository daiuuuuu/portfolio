# 移动端适配 · 完整实施计划

## 目标
把当前以 1920×1080 桌面为主的站点，适配到移动端（320-430px）、平板（768-1024px）、桌面各分辨率（1280/1366/1440/1536/1920）、超宽屏（2560+）。**移动优先**，社区共识做法。

## 断点体系（沿用 Tailwind 默认，移动优先）
| 断点 | 宽度 | 用途 |
|---|---|---|
| base | 0-639 | 手机竖屏（320/375/390 目标） |
| sm | 640+ | 手机横屏/小平板 |
| md | 768+ | 平板 |
| lg | 1024+ | 笔记本 |
| xl | 1280+ | 标准桌面 |
| 2xl | 1536+ | 大屏/超宽屏 |

## 阶段 1 · 断点布局（核心工作量）
逐组件改造，每改一个用 Playwright 在 375/768/1024 截图验证：

1. **TopNavBar**：`lg` 以下导航链接 `hidden` → **加汉堡菜单**（下滑抽屉/侧滑），HOME/OVERVIEW/Q&A/NEXT/Top 全进菜单；触摸目标 ≥44px
2. **HeroSection**（最复杂）：
   - 印章 `w-[360px] right-[152px]` → 移动端缩放/重定位
   - 雕塑 `h-full` 绝对定位 → 移动端缩小或调整位置
   - 45° 色带组（`marginLeft:-140, marginTop:300`）→ 移动端调参避免溢出
   - 书签 tag `px-[5%]`、底部元数据 → 窄屏排布
3. **ProjectIndexSection 卡片**：`min-h-[calc(100vh-4rem)]` + 12 列 → 移动端纵向堆叠；封面图 `w-[200px]` 适配
4. **ProjectDetail Hero**：`md:grid-cols-2` 50/50 → 移动端文字/图堆叠，标题字号 clamp 已流体
5. **各详情页区块**：技术栈/质量核对 3 列 → 移动 1 列；工程亮点 3/9 分栏 → 移动堆叠；交付目录黑底树横向滚动已有
6. **Footer/Contact**：移动端纵向排布

## 阶段 2 · 流体排版与间距
- 字号已用 clamp（保留），检查是否纯 `vw`（须 `rem+vw` 组合，防用户缩放崩坏）
- 区块 padding（`py-16/py-21`、`px-margin-outer`）→ 流体 `clamp()`，超宽屏/小屏都协调
- 320px 最小宽度全站可读性检查

## 阶段 3 · 触摸交互与超宽屏
- hover-only 交互（卡片负片反转、cursor 特效）→ 触摸设备加 tap 替代（matchMedia pointer:coarse 判断）
- 防横向滚动：`overflow-x: hidden` 兜底（注意不能误伤钉住横向滚动区 XCU showcase）
- 刘海屏 safe-area inset
- 超宽屏（>1920）：内容 max-width（~1440-1600px）居中，避免文字拉太宽

## 阶段 4 · 测试与验收
- Playwright 自动截图矩阵：**320 / 375 / 390 / 768 / 1024 / 1280 / 1440 / 1920 / 2560**
- 检查项：无横向滚动、无文字溢出、触摸目标 ≥44px、图片不破版
- 已部署站点 + dev server 双验证

## 风险与注意
- **XCU 钉住横向滚动**是 reveal 系统的敏感点——改布局后必须回归 XCU 文字（用实时几何 exit 已根治，但别改回 scrub）
- GSAP 动画大量 transform/clip-path——改布局别破坏 `data-reveal` 结构
- 每个阶段改完 build + Playwright 回归，避免积累问题

# 端适配 v3 — 桌面等比混合方案（2026-08-17 用户定夺）

> 用户实机看过 v1（纯响应式重排）后明确：**不要重排成移动端单列**。v2（纯桌面等比缩放）被浏览器实测否决（`html{zoom}` 会二次缩小 vw 单位；`width=1920` 视口被现代 Chrome 忽略）。最终用户拍板为 **「结构保列 + 正文整行」的智能混合**。

## 决策记录
- 实测探针：`html{zoom}` → `13vw` 由 49px 变 10px（vw 被二次缩放，不可行）；视口 `width=1920` → innerWidth 仍 375（被忽略，不可行）。**结论：纯"整页等比缩放"在 vw 密集型站点上不可行。**
- 硬矛盾：375px 手机宽度下，「桌面多列比例」「中文正文可读（≥15 字/行）」「塞进窄屏」三者不能同时完美。
- 用户选：**结构区块保持桌面多列构图，大段正文在手机端整行排列保证可读**。

## 落地规则（「结构保列 + 正文整行」）
| 类别 | 区块 | 移动端处理 |
|---|---|---|
| **结构/标签**（保列） | Profile 统计 4 列 · 技能 4 列 · 技术栈 3 列 · 质量核对 3 列 · Showcase 组件样例 2 列 · 图片网格 | 保持桌面列数，仅压缩内边距 |
| **正文/散文**（整行） | 卡片简介 · Overview/背景/工程亮点/方法对比/流程对比 · 方案卡/流程/设计特点 · 详情 Hero 副标题 | 手机端回退为整行排列（`md:` 前缀），保证中文可读 |
| **首屏/换页/导航** | Hero · Curtain · 汉堡导航 | 保持移动端适配（用户明确要求） |

# 端适配 v4 — 用户实机反馈修复（2026-08-17）

## 1. 移动端关闭吸附
- **决策**：用户明确「移动端不要吸附」。桌面（≥768px）保留 smoothWheel 的 glide 吸附。
- **实现**：`ProjectIndexSection.tsx` 的 `setGlideRedirect` + `wheel:settle` 兜底对齐整体包进 `gsap.matchMedia('(min-width: 768px)')`——<768px（手机/窄窗）不注册吸附,旋转横屏/缩窗自动跟随。
- 注：移动端触摸本来就是原生滚动、不触发 wheel,此前也从未真正吸附;此举是显式兜底,杜绝任何窄屏误吸附。

## 2. 项目页英雄区「方块叠文字」修复
- **根因**：英文大标题 `whitespace-nowrap` 且字号用 per-project vw clamp(`8.2vw` 等)。在 1024–1600px 桌面宽度,标题比左半栏(~683px)宽,**向右溢进右侧封面图区**,末尾文字叠在深色封面上看不见(视觉复现确认)。
- **实现**：`ProjectHero.tsx` 加 JS 自适应——挂载时把标题重置为 CSS 尺寸再测量,超出容器则按比例收缩(仅缩不放),resize 重算;标题容器加 `overflow-hidden` 兜底。所有项目标题、任何宽度都保证不溢栏。
- **验证**：1366px 下最长标题「XCU SCI-TECH PARK」(16 字符)完整显示、与封面界限清晰无重叠;390px 无回归;横溢审计全绿;hero 竞态回归 5/5。
